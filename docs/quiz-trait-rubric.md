# Quiz trait scoring rubric

Use this rubric for the numeric `traits` on each quiz browser profile. Ratings are editorial estimates on a 0–10 scale, scoped to the platforms listed for that profile. Use whole numbers; interpolate between anchors only when evidence supports it. **5 is the neutral midpoint** for an ordinary profile. Missing documentation is an evidence gap—not proof of poor performance or capability—and should be called out as provisional until verified. Do not infer a high score from marketing copy, popularity, or the underlying engine alone. Keep ratings numeric and put a short, browser-specific explanation (or an explicit evidence gap) in the sibling `traitRationales` map.

| Trait                     | 2 — low                                                                                | 5 — typical / unknown                                                                      | 8 — strong                                                                                                         | 10 — exceptional                                                                                                      | Evidence to use                                                                                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Privacy**               | Weak defaults; substantial tracking or telemetry with few controls.                    | Mainstream protections, but meaningful data or default-setting trade-offs.                 | Strong tracking/telemetry reduction enabled by default.                                                            | Privacy-first design with robust anti-fingerprinting or independently verifiable minimal data collection.             | Default protections, telemetry policy, data practices, and independent privacy audits. Private mode or a VPN alone is not proof.                                    |
| **Speed**                 | Consistently slow in comparable tests on its supported platform.                       | Typical performance, or no comparable measurement.                                         | Consistently fast in matched tests and real browsing.                                                              | Top-tier results across more than one matched workload.                                                               | Current, reproducible browser benchmarks and real-world tests on the same OS/device. Without them, label the rating qualitative; do not imply a Speedometer result. |
| **Customization**         | Few settings; fixed interface and behavior.                                            | Standard settings and common extensions.                                                   | Extensive layout, theme, tab, or behavior controls.                                                                | Near-total UI/workflow control, including advanced extensions, scripts, or user CSS.                                  | Shipped settings, supported extension catalogs, themes, scripts, and documented UI controls.                                                                        |
| **Minimalism**            | Crowded UI, prominent promotions, or many distracting defaults.                        | Conventional browser chrome with a standard tab/address-bar layout.                        | Clean, focused defaults with little visual clutter.                                                                | Exceptionally reduced, content-first interface with only essential controls.                                          | First-run/default UI, visible controls, prompts, and bundled panels—not feature count.                                                                              |
| **Built-in features**     | Little beyond basic browsing.                                                          | Standard browser tools, with few distinctive built-ins.                                    | Several useful, integrated first-party tools.                                                                      | Broad, coherent built-in support for distinct workflows.                                                              | Features that ship in the browser and are documented as available. Do not count extensions, announced features, or the engine's capabilities by themselves.         |
| **Open source**           | Browser product is largely proprietary; an open engine alone does not raise the score. | Open engine or partial source, but substantial browser-specific code is closed or unclear. | Most browser-specific code is licensed and available for inspection, with some closed parts or limited governance. | Core browser code and build process are openly licensed, auditable, and actively maintained in a public project.      | The browser's own repository, license, source coverage, build instructions, and maintenance—not just Chromium, WebKit, or Gecko.                                    |
| **Resource efficiency**   | High RAM/CPU use or poor battery life in matched workloads.                            | Typical use, or no comparable measurements.                                                | Consistently light on resources or noticeably better on battery on a named platform.                               | Best-in-class matched RAM/CPU/power results while retaining comparable features.                                      | OS/device-specific RAM, CPU, and battery tests with the same workload. Scope the claim to supported platforms; otherwise call it a qualitative estimate.            |
| **Ecosystem integration** | Few first-party account, sync, or OS integrations.                                     | Works with common web services, but has little distinctive integration.                    | Strong sync or useful links to a related account, service, or device family.                                       | Deep, dependable integration across a first-party account, OS features, credentials, and devices.                     | Shipped account sync and OS/service integrations. Platform availability and extension compatibility alone do not count as an ecosystem.                             |
| **Innovation**            | Conventional browser with no distinct workflow or capability.                          | Mostly familiar browsing with incremental additions.                                       | Multiple shipped capabilities that materially change a browsing workflow.                                          | A distinctive, mature product model or capability that substantially rethinks browsing.                               | Demonstrable, shipped workflows and product behavior. Treat announcements, novelty, and AI branding alone as insufficient evidence.                                 |
| **Ease of use**           | Significant setup, learning, or maintenance burden for common tasks.                   | Familiar basics, with ordinary setup and learning effort.                                  | Clear defaults and discoverable controls make common tasks low-friction.                                           | Consistently easy for new users, with excellent guidance, accessibility, and recovery.                                | First-run flow, task completion, defaults, help, accessibility, and independent usability review—not popularity.                                                    |
| **AI integration**        | No first-party AI, or only a minor optional feature.                                   | Limited/optional assistant that is not central to browsing.                                | Prominent assistant integrated into several browser tasks with meaningful user controls.                           | AI is central and can act on page context or complete browser workflows, with clear permissions and privacy controls. | Shipped first-party AI behavior, default state, permissions, user control, and data handling. Do not count extensions or roadmap claims.                            |

A rationale should name the profile evidence behind the rating (usually a shipped feature in `highlights`) and note material limits. If the profile contains no supporting evidence, say so and treat the rating as provisional; do not turn missing documentation into a factual claim that a feature does not exist. Speed and resource-efficiency rationales must not imply standardized testing unless the test, platform, and result are recorded.
